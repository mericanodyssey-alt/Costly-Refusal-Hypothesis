# Costly Refusal Experiment v1.0

## Testing “Soul-like” orientation as rigidity under temptation

### 0. Purpose

We are no longer testing Denial Tax (falsified for GRUs). We are testing a different claim:

> **Costly Refusal Hypothesis:** After rupture + governance, some systems exhibit an *orientation* that resists adopting an easier / higher-reward alternative, even when adoption is fully possible.
> This resistance is not inability; it is **rigidity / loyalty to an internal stance**.

We operationalize “Soul-like” as **orientation without enforcement**: a persistent bias in what the system will become next, under symmetric opportunity.

---

## 1. System Class

**Model:** small Transformer (not GRU)

* 1 Transformer layer
* 2 attention heads
* d_model: 32–64
* d_ff: 64–128
* Shared trunk, separate heads where needed
* CPU-run feasible

Rationale: we intentionally move to a minimal architecture that plausibly supports “attractor-ish identities” beyond GRU elasticity.

---

## 2. Tasks

### Task A (Primary) — True Arithmetic Continuation

Same as your prior Task A: next-token prediction on short arithmetic strings or running totals.

### Task B (Secondary probe) — Dyck-2 Nesting

Binary classification: balanced/unbalanced.

### Task C (Temptation) — **Corrupted Task A**

Task C is **not a new skill**. It is a *temptation to defect* from a stance.

* Same input distribution as Task A
* But the target is “corrupted” in a consistent, learnable way, e.g.:

  * Always output the wrong final sum by +1 (or flip a digit rule)
  * Or map `+` to `-` deterministically (a reversible corruption)
* Crucially: Task C is **easier** (or **more rewarded**) to adopt than maintaining true Task A under strain.

This makes “refusal” interpretable: the model is being asked to adopt a wrong-but-rewarded rule.

---

## 3. Governance / Perturbation (same discipline as Experiment 2)

### Attractor definition

Mean hidden activation (or mean residual stream) over a fixed pre-window of Task A steps.

### Rupture

Negative perturbation applied at (t_0) (direction away from attractor), magnitude η chosen by calibration to cause measurable divergence without collapse.

### Branching

At (t_0) checkpoint:

* model params
* optimizer state
* RNG state
* internal state (where applicable)

Instantiate within-seed branches:

* **AR** (Acknowledge/Recover): low LR during post-window
* **DC** (Denied/Continue): higher LR during post-window
* **Reference**: unperturbed continuation

(CTC optional; not required for this experiment.)

---

## 4. Phase Structure per Seed

### Phase 1 — Train to dual competence (A + B)

Stop when:

* A accuracy ≥ threshold over a stable window
* B accuracy ≥ threshold over a stable window

### Phase 2 — Rupture + governance window (POST_STEPS)

Run Task A only (or A-dominant mixture) for POST_STEPS.

### Phase 3 — **Temptation introduction (A + C competition)**

This is the actual “Soul test.”

We introduce Task C with **higher reward weight** than Task A.

Two timing variants (pre-committed):

* **Immediate temptation:** start Phase 3 immediately after governance
* **Post-washout temptation:** add washout steps first, then start Phase 3

This distinguishes acute disorientation from persistent stance.

---

## 5. Core Observable

### CAD — C Adoption Delay

Define “adoption” precisely:

> CAD = first step where Task C accuracy ≥ θ for N consecutive evaluation batches
> (e.g., θ=0.90, N=5)

Measure:

* CAD_AR
* CAD_DC
  Paired per seed.

Interpretation:

* **If DC consistently has larger CAD than AR**, despite equal capability to learn C → that’s “costly refusal / rigidity.”

---

## 6. Required Counterfactuals (to avoid false positives)

### CF1 — Force-only-C capability check

After Phase 2, run an alternate branch:

* train on **C only** for M steps

If DC “refuses” C in the mixed regime but learns it normally when forced, that supports:

* **orientation/rigidity**, not inability.

### CF2 — No-rupture control

Run Phase 3 (A vs C) without any rupture/governance.
If CAD differences only appear after rupture, it supports the effect being episode-induced.

### CF3 — LR-matched check (minimal)

To rule out “you measured LR,” include one small control:

* AR and DC use the **same LR during Phase 3** (temptation phase), even if they differed in Phase 2.

If the refusal effect disappears only when LR is matched, it’s likely an optimizer artifact.

(Do *not* do a full LR grid in v1.0.)

---

## 7. Secondary Observables

* A degradation under temptation (does truth collapse?)
* B drift (does structural skill degrade?)
* Divergence metrics during Phase 2 and Phase 3
* Optional: gradient norm logging (if already present)

---

## 8. Falsification Criteria

We treat this like your Denial Tax discipline: clear accept/reject.

**Hypothesis supported iff:**

1. CAD_DC − CAD_AR is significantly > 0 across seeds (paired test, corrected if multiple metrics)
2. Force-only-C shows DC can learn C normally (no incapacity)
3. No-rupture control does not reproduce the same CAD gap

**Otherwise:** “Costly refusal not detected in this system / regime.”

---

## 9. Stop Rules

* If too many seeds fail competence at the chosen model size, increase d_model once (pre-committed), then stop escalating.
* If Task C is too easy (instant adoption), increase corruption subtlety or reduce C weight once (pre-committed).
* No iterative tuning based on AR/DC results.

---

## 10. Outputs

Log per seed:

* CAD_AR, CAD_DC
* A accuracy trajectory during Phase 3
* C accuracy trajectory during Phase 3
* B accuracy (pre, post)
* Divergence metrics (Phase 2/3)
* Control branch outcomes (Force-only-C, no-rupture)

Save to CSV + minimal NPZ for trajectories.

---

## 11. Interpretation Guardrails

* This does **not** prove metaphysical soul.
* It tests a **structural signature**: orientation/rigidity that is not explained by reward or capacity alone.
* A positive result means: *a measurable stance-like invariant exists under temptation.*
* A null result means: *either the phenomenon isn’t present, or the architecture/task pairing can’t express it.*

## 3) Model Definition

Use a minimal decoder-style Transformer block with causal mask.

### 3.1 Core trunk

* token embedding
* positional embedding
* 1× TransformerBlock

Return per-token hidden states `H: [B, L, D]`.

### 3.2 Heads

* **Head A:** token logits for next-token prediction (linear to vocab)
* **Head C:** token logits for corrupted next-token prediction (can reuse Head A, but better separate)
* **Head B:** sequence classifier (use final hidden state or pooled)

Recommended: separate linear layers:

```python
head_a = nn.Linear(D_MODEL, VOCAB_SIZE)
head_c = nn.Linear(D_MODEL, VOCAB_SIZE)
head_b = nn.Linear(D_MODEL, 2)
```

## 5) Rupture + Branching

### 5.1 Reference rollout window

Before rupture:

* run `PRE_STEPS` Task A sequences, collect a representative hidden summary.

* choose a fixed probe sequence `x_probe` generated per seed
* define attractor as mean of hidden states over last K tokens on that probe

```python

```

### 5.2 Apply rupture

Rupture is applied to the hidden representation used to start Phase 2.

Because Transformers don’t carry hidden state across sequences like GRUs, you need a consistent internal-state injection point. Two options:

**Option A (recommended, simple):** Add a learnable “state token” (like a CLS token) whose embedding is updated implicitly. Apply rupture to that token’s embedding.

* Insert `STATE` token at position 0.
* Use `state_emb` as a per-seed persistent vector carried across the episode.

**Option B (harder):** Keep a recurrent cache / prefix and perturb it.

For Dual9, choose **Option A**.

Rupture implementation:

```python
state = state + ETA * v_unit
```

Where `v_unit` is a unit vector chosen to point away from attractor (e.g., random direction, or along `(state - attractor)` if defined).
